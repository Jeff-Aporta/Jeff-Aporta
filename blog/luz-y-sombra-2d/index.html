Luz y sombra en 2D

Una guía narrada para crear visibilidad y sombras dinámicas en tus juegos, paso a paso y con demos que puedes tocar.

Jeffrey Agudelo · 2026-10-27 · Guía narrada, Canvas 2D, Geometría, Videojuegos, TypeScript

Construimos desde cero el clásico efecto de luz que proyecta sombras sobre una escena 2D: rayos, intersecciones, el polígono de visión, sombras suaves y varias luces. Cada paso trae su narración y su demo interactiva.

1. Bienvenida

Hola, soy Jeff. En esta guía vamos a construir juntos un efecto que seguro has visto en muchos juegos 2D: una luz que ilumina la escena y proyecta sombras detrás de los obstáculos. Mueve el cursor sobre la demo para ver a dónde vamos a llegar. Cuando quieras, pasa al siguiente paso.

Este efecto se usa en juegos de sigilo, en mazmorras con niebla de guerra y en cualquier juego donde **lo que ve el personaje** importa. No necesitas un motor gráfico: con **un poco de geometría** y el **canvas 2D** del navegador es suficiente. Lo construimos en **diez pasos**, cometiendo a propósito los mismos errores que uno comete la primera vez, para entender por qué la solución final funciona.

2. La escena

Todo empieza por describir el mundo. Nuestra escena es un rectángulo con seis obstáculos, y cada pared es un segmento: un punto de inicio y un punto final. Los bordes también son segmentos, porque la luz tiene que chocar contra algo.

La escena mide **840 × 360** píxeles. Cada pared es un **segmento** con un punto `a` y un punto `b`; un polígono se convierte en sus segmentos uniendo cada vértice con el siguiente.

type Punto = { x: number; y: number };
type Segmento = { a: Punto; b: Punto };

// Un polígono cerrado se convierte en sus segmentos: cada vértice con el siguiente.
function poligono(vertices: Punto[]): Segmento[] {
  return vertices.map((a, i) => ({ a, b: vertices[(i + 1) % vertices.length] }));
}

const ESCENA: Segmento[] = [
  ...poligono([{ x: 0, y: 0 }, { x: 840, y: 0 }, { x: 840, y: 360 }, { x: 0, y: 360 }]), // borde
  ...poligono([{ x: 100, y: 150 }, { x: 120, y: 50 }, { x: 200, y: 80 }, { x: 140, y: 210 }]),
  // …y los demás obstáculos
];

3. Un rayo

La idea central es lanzar rayos desde la luz y averiguar dónde chocan con las paredes. Empecemos con uno solo. El rayo y el segmento se escriben como un punto más una dirección, y el producto cruz nos dice dónde se cruzan, o si son paralelos. Nos quedamos con el choque más cercano.

Cualquier recta se puede escribir en **forma paramétrica**: un punto de partida más una dirección multiplicada por un número. - El **rayo** es `origen + dirección · t`, con `t ≥ 0` (solo hacia adelante). - El **segmento** es `a + (b − a) · u`, con `0 ≤ u ≤ 1` (solo entre sus extremos). Para resolver el sistema usamos el **producto cruz** en 2D, `cruz(p, q) = p.x · q.y − p.y · q.x`, que además avisa cuando las rectas son **paralelas**.

function interseccion(rayo: Segmento, seg: Segmento) {
  const r = { x: rayo.b.x - rayo.a.x, y: rayo.b.y - rayo.a.y }; // dirección del rayo
  const s = { x: seg.b.x - seg.a.x, y: seg.b.y - seg.a.y };     // dirección del segmento
  const den = r.x * s.y - r.y * s.x;                           // cruz(r, s)
  if (Math.abs(den) < 1e-12) return null;                      // paralelos

  const q = { x: seg.a.x - rayo.a.x, y: seg.a.y - rayo.a.y };
  const t = (q.x * s.y - q.y * s.x) / den; // distancia a lo largo del rayo
  const u = (q.x * r.y - q.y * r.x) / den; // posición sobre el segmento

  if (t < 0 || u < 0 || u > 1) return null; // detrás del rayo o fuera del segmento
  return { x: rayo.a.x + r.x * t, y: rayo.a.y + r.y * t, t };
}

Probamos el rayo contra **todos** los segmentos y nos quedamos con el de **menor `t`**: el más cercano. Lo que hay detrás queda en sombra.

4. Rayos en todas direcciones

Una luz no ilumina en una sola dirección. Lo más intuitivo es lanzar muchos rayos repartidos en círculo, por ejemplo cincuenta, y guardar el choque más cercano de cada uno. Mira cómo se ven en la demo.

const choques = [];
for (let k = 0; k < 50; k++) {
  const angulo = (k / 50) * Math.PI * 2;
  const rayo = { a: luz, b: { x: luz.x + Math.cos(angulo), y: luz.y + Math.sin(angulo) } };
  const choque = masCercano(rayo); // el de menor t entre todos los segmentos
  if (choque) choques.push(choque);
}

5. El primer polígono (y su error)

Si unimos los choques en orden, obtenemos la zona iluminada. Pero fíjate en las esquinas: el polígono las corta o las atraviesa. Subir a miles de rayos solo esconde el problema. La clave es que la sombra solo cambia en los vértices de los obstáculos.

Con 50 rayos nunca acertamos justo en los vértices, y subir a 500 o 5000 rayos solo esconde el problema mientras el rendimiento se desploma.

La clave del efecto. La forma de la sombra solo cambia **en los vértices** de los obstáculos. Entre dos vértices la luz recorre la pared en línea recta. No necesitamos miles de rayos: necesitamos **un rayo por vértice**.

6. Rayos hacia cada vértice

Ahora lanzamos un rayo hacia cada vértice de la escena. Hay una trampa: cuando el rayo roza una esquina, la luz puede seguir de largo. Por eso lanzamos dos rayos extra, desviados un ángulo diminuto a cada lado. Uno choca con la esquina y el otro sigue hasta el fondo.

const DESVIO = 0.00001;

const angulos = vertices(ESCENA).flatMap((p) => {
  const a = Math.atan2(p.y - luz.y, p.x - luz.x);
  return [a - DESVIO, a, a + DESVIO];
});

7. El polígono de visión

Los choques ya son exactos, pero llegan desordenados. Los ordenamos por ángulo alrededor de la luz y los unimos en ese orden. El resultado es el polígono de visión: todo lo que la luz alcanza, con las esquinas perfectas y apenas unas decenas de rayos.

function poligonoVision(luz: Punto): Choque[] {
  const choques = [];
  for (const angulo of angulos) {
    const choque = masCercano(rayoAngulo(luz, angulo));
    if (choque) choques.push({ ...choque, angulo });
  }
  return choques.sort((p, q) => p.angulo - q.angulo); // en orden alrededor de la luz
}

// Dibujarlo es recorrer los puntos y rellenar.
ctx.beginPath();
ctx.moveTo(poli[0].x, poli[0].y);
for (const p of poli.slice(1)) ctx.lineTo(p.x, p.y);
ctx.fill();

8. Sombras suaves

Las sombras reales no tienen bordes perfectos, porque las luces tienen tamaño. Un truco barato y muy efectivo es dibujar la luz principal y diez luces más a su alrededor, casi transparentes. Donde se superponen, la luz se suma, y en los bordes aparece la penumbra.

const radio = 10;
for (let k = 0; k < 10; k++) {
  const a = (k / 10) * Math.PI * 2;
  const otra = { x: luz.x + Math.cos(a) * radio, y: luz.y + Math.sin(a) * radio };
  ctx.globalAlpha = 0.2;
  rellenar(poligonoVision(otra));
}
ctx.globalAlpha = 1;
rellenar(poligonoVision(luz));

9. Del polígono a la escena

La luz blanca todavía parece un diagrama. Para que se vea como un juego usamos dos imágenes: un fondo en penumbra y un frente iluminado. El polígono de luz funciona como máscara, y el frente solo se pinta donde ya había luz.

Con `globalCompositeOperation = 'source-in'`, al dibujar el frente solo se pinta donde ya había píxeles de luz. El fondo queda debajo, como el fondo del lienzo.

dibujarLuz(ctx, luz);                         // polígonos blancos
ctx.globalCompositeOperation = 'source-in';  // lo siguiente solo donde ya hay píxeles
ctx.drawImage(frente, 0, 0);
ctx.globalCompositeOperation = 'source-over'; // volver al modo normal

10. Más de una luz

Como cada luz es solo un conjunto de polígonos, agregar luces es repetir el dibujo antes de aplicar la máscara. En la demo hay dos, una a cada lado, que se mueven en sentidos opuestos con el cursor. Fíjate cómo las sombras se cruzan y se suman.

Rendimiento. Cada polígono lanza **3 rayos por vértice** y prueba cada rayo contra **todos los segmentos**: unas 3·V·S pruebas. Para escenas pequeñas sobra; en mapas grandes conviene filtrar los segmentos cercanos (una cuadrícula o un árbol espacial) y limitar el alcance de cada luz.

11. Para terminar

Y listo. Con una función de intersección, un rayo por vértice y ordenar por ángulo tienes el núcleo de cualquier sistema de visibilidad 2D. Desde aquí puedes hacer una linterna, decidir qué enemigos ve el jugador o mezclar luces de colores. Si lo llevas a tu juego, cuéntame cómo te fue. Gracias por acompañarme.

- **Linterna:** filtra los ángulos dentro de un cono. - **Sigilo:** usa el polígono para decidir **qué enemigos ve el jugador**. - **Ambiente:** combina varias luces de colores. Las demos son un web component del portafolio, `<ja-luz-demo>`, que recibe el paso como propiedad y solo anima mientras está a la vista.
